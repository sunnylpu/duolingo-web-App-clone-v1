# Phase 30 — Daily Quests + Missions + Challenge System

**Hour 12 of the remaining roadmap**

We now have a substantial platform:

```text
🇬🇧 English → 8 Units → 32 Skills → 96 Lessons → 576 Exercises
🇪🇸 Spanish → 5 Units → 20 Skills → 60 Lessons → ~360 Exercises
🇫🇷 French  → 3 Units → 12 Skills → 36 Lessons → ~216 Exercises
```

And the learner now has:

```text
Learning Path
Course Switching
Lesson Engine
Hearts
XP
Streak
Daily Goal
Achievements
Leaderboard
Friends
Smart Review
Search
Vocabulary Explorer
Course/Unit Mastery
```

At this point, the next high-value feature should be a **daily mission layer**.

Why?

Because the learner currently has to decide:

> "What should I do today?"

A mature gamified learning product answers:

> "Here are today's missions."

---

# Phase 30 objective

Build:

```text
🎯 Daily Quests
🏆 Weekly Challenge
```

The learner should see:



# 4. Daily quest generation

Each day generate **3 quests** per learner.

Example:

```text id="b77q9b"
Quest 1:
Complete 2 lessons
Reward: +20 XP

Quest 2:
Earn 30 XP
Reward: +15 XP

Quest 3:
Answer 10 correctly
Reward: +20 XP
```

Do not generate them randomly every API request.

They must be stable for the day.

---

# 5. Deterministic daily quests

Use the user's:

```text id="9x6w3e"
user_id
+
date
```

to deterministically select/generate that day's quests.

This prevents:

```text id="n8g8fk"
refresh page
→ quests change
```

The same day should show the same missions.

---

# 6. Daily reset

Don't use a frontend midnight timer.

Use the backend's existing application timezone:

```text id="4wz1oa"
APP_TIMEZONE
```

When the date changes:

```text id="4g9o4s"
new DailyActivity
→ new daily quests
```

No cron job is required for the MVP.

---

# 7. Quest progress

Quest progress should update automatically based on existing events.

For example:

```text id="nyk1zj"
Lesson completed
      ↓
LESSONS_COMPLETED += 1
XP_EARNED += lesson XP
```

And:

```text id="g0zgpf"
Correct exercise
      ↓
CORRECT_ANSWERS += 1
```

Don't ask the frontend to call:

```text id="9y0g1c"
POST /quests/progress
```

after every action.

The backend should derive quest progress from the actual domain event.

---

# 8. Quest completion

When:

```text id="jsc8ku"
current_value >= target_value
```

set:

```text id="c0yuo8"
completed = true
```

and award:

```text id="i0n5hr"
reward_xp
```

exactly once.

---

# 9. Prevent quest reward duplication

Critical.

Example:

```text id="8c9x5u"
Quest target = 2 lessons

Lesson 1
→ 1 / 2

Lesson 2
→ 2 / 2
→ +20 XP

retry same completion
→ +0
```

Use:

```text id="gv2f9z"
UserQuest.completed
+
database constraints
```

---

# 10. Quest reward transaction

When an action completes a quest:

```text id="uq2r27"
BEGIN

complete lesson
update XP
update daily activity
update quests
award quest XP

COMMIT
```

This keeps quest progress consistent with the event that caused it.

# Phase 31 — Notifications + Reminder System + Daily Engagement

**Hour 13 of the remaining roadmap**

We now have a strong daily loop:

```text
Home
 ↓
Daily Quests
 ↓
Learn / Review
 ↓
XP
 ↓
Streak
 ↓
Achievements
 ↓
Leaderboard
```

But the learner still has to **remember to come back**.

Phase 31 adds a lightweight notification/reminder system without introducing push infrastructure yet.

The goal is:

```text
🔔 Daily reminder
🔥 Streak reminder
🎯 Quest reminder
🏆 Achievement notification
📚 Course progress reminder
```

The system should be designed so that later, when we deploy on AWS, it can evolve into email/push notifications without rewriting the core domain.

---
